### 1.3 主题色机制（核心）

运行时在 `:root` 注入 CSS 变量，主题样式表全部引用变量：

```css
:root{
  --md-primary-color:#0F4C81;      /* ← 主题色，点色板即改这一处 */
  --md-font-size:16px;
  --md-font-family:-apple-system-font,BlinkMacSystemFont,Helvetica Neue,PingFang SC,…;
  --blockquote-background:#f7f7f7;
}
```

因此「一键全局换色」是**变量驱动的全局重绘**，标题、边框、表头、引用块全部跟着变色 —— 这是 v2 「事后按色值精确替换」做法差得远的根本原因。

## 二、微信「内容结构检测」权威规则（来自官方校验器源码）

规范：https://developers.weixin.qq.com/doc/service/guide/product/plugin_spec.html
实现：https://github.com/wechatjs/verify-article-structure-spec （`cli/engine/rules/*.ts`）

| 规则 | 判定 | 我们的输出 |
|---|---|---|
| **3 字体** | 内联 `font-family` **不以 `"mp-quote", PingFang SC, system-ui, -apple-system` 开头即违规** | ❌ **每个元素都写了 `font-family:-apple-system,"PingFang SC",…` → 全线违规（这就是仍然告警的原因）** |
| 1.6 text-align | 内联值为 `start` / `end` | ✅ 已丢弃 |
| 1.4 width | `img`（非 ProseMirror-separator）、**`table > thead > th` 一律为候选**、非 img/svg 的固定宽度（非 `auto`/`100%`） | ⚠️ `<th>` 会命中 → 应把 `thead/th` 归一成 `tbody/td` |
| 1.5 height | 内联 `height:0` 且含文字 | ✅ 不输出 |
| 1.8 pre | `<pre>` 且含文字 | ✅ 不输出 |
| 1.1 opacity | `img` 的 `opacity:0` | ✅ 不输出 |
| 1.2 caret-color | 透明光标色 | ✅ 不输出 |
| 1.3 line-height | 行高 < 字号且多行（实测布局） | ✅ 行高均 ≥ 字号 |
| 2.1 嵌套 | `MAX_STYLE_LEVEL = 15`（源码实际阈值）触发后模拟删除冗余包裹层 | ✅ 深度仅 3 |
| 2.2 span[leaf] / 2.3 section[nodeleaf] | 行内容器不得含块级元素 | ✅ 不产生这两个标记 |

- 顶栏最左是 **Word 式菜单条**；每个菜单的下拉面板内按 **Word 功能区式分组**（组名 + 控件 + 分隔线）排列。

| **编辑** | 撤销 · 重做 · 清除选区格式 |
| **格式** | 字体组：字号 · 加粗 · 斜体 · 下划线 · 删除线 · 字色 · 文字背景(含「无」)<br>段落组：对齐 4 种 · 首行缩进 · 行距 · 段距 · **段落底色**(含「无」) · 段落边框 + 边框色 |

### 3.3 主题色引擎（对齐 nihaotk 效果）

1. **转换时**保存 `originHTML`（内联+合规归一化之后的干净基线）。
2. 从基线里**识别品牌色族**：按元素权重（h1/h2/h3/th/blockquote/strong）投票，取主导彩色。
3. 选任意主题色时：`originHTML → 色族映射 → 预览/输出`，映射规则：
   - 同 RGB 不同透明度 → 换 RGB 保 alpha（浅底跟着走）
   - 同色相（±12°）、饱和度接近的**明暗变体** → 保明度差、换色相/饱和度（深色标题线、浅色底纹一起走）
4. 因此切换色板是**整篇重绘**且**可从基线反复重算**（无累积漂移），效果与 nihaotk 的变量重绘一致。

### 3.4 卡片 vs 色块（明确区分）

| | 色块 | 卡片 |
|---|---|---|
| 形态 | 纯底色盒：`background + padding + radius`，**无边框** | 带边框容器：`background + border(1px~4px) + radius + padding` |
| 插入 | 插入 → 色块 | 插入 → 卡片 / 引用卡片 |
| 编辑 | 样式 → 色块组（底色 / 去底色） | 样式 → 卡片组（背景 / 边框色 / 位置 / 宽度 / 移除） |
| 识别 | 有底色、无可见边框 → 色块 | 有可见边框 → 卡片 |
| 提示 | 状态栏显示「目标：色块」 | 状态栏显示「目标：卡片」 |

### 3.5 公众号合规（针对仍然告警的真因）

1. **永不输出 `font-family`**：无论原文怎么写，转换时一律剥离；菜单中不再提供字体系选择（帮助菜单里说明原因）。
2. **表格归一化**：`<thead>/<th>` → `<tbody>/<td>`（内联样式原样保留，视觉不变），避免 `<th>` 命中 width 候选。
3. 维持：无 `start/end` 对齐、无 `pre`、无固定宽高、无 `opacity`/`caret-color`、行高 ≥ 字号、嵌套深度远低于 15。
4. 新增 `test-wechat-spec.html`：**移植官方 12 条规则**逐条自检，作为永久回归测试。

## 五、实施记录（与计划的差异）

| 项 | 计划 | 实际实现 | 说明 |
|---|---|---|---|
| 主题色引擎 | 「基线 + 色族映射」 | 基线登记（逐元素/属性记录原值 + 色族判定）→ 每次换色**从基线重导** | 比"当前值上叠加"更强：往返切换零漂移，无关配色零误伤 |
| 饱和度映射 | 未细化 | 上限从 0.98 修正为 **1.0** | 实测发现高饱和主题色（`#009874`）被削成 `rgb(2,150,115)` |
| 标题样式 | 可选 | 已实现并接入主题引擎 | 施加后跟随后续换色 |
| 撤销后的主题基线 | 未考虑 | DOM 整体替换后自动以当前主题色重新登记 | 避免撤销后主题色失效 |
